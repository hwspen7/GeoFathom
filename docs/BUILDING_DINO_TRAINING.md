# DINOv3 building learning

The original HOT ONNX graph is an inference teacher, not a recoverable PyTorch checkpoint. This path trains a new DINOv3 ViT-S/16 feature-pyramid decoder from an operator-provided, licensed local Hugging Face `config.json` and `model.safetensors` (facebook/dinov3-vits16-pretrain-lvd1689m). It makes no implicit downloads and never loads arbitrary pickle. Install the optional `building-dino` dependencies; CUDA PyTorch is separate from ONNX Runtime. A random tiny CI fixture only tests software contracts, not pretrained accuracy.

Expand the original dataset using `scripts/prepare_building_study.py --train-per-city 36 --train-patches-per-scene 8 --evaluation-per-city 12 --preserve-evaluation OLD/dataset.json --output NEW`. Counts depend on the publisher's patch availability; validation/test byte identities must match. Training requires at least 100 chips from two or more cities and at least 12 independent source groups per city. This is still a limited domain-adaptation corpus; no claim of pretraining disjointness.

Run `python scripts/building_dino_train.py --dataset NEW/dataset.json --backbone LOCAL_BACKBONE --output NEW_RUN --device cuda --mode decoder --precision bf16 --teachers hotosm-dinov3s-buildings-fp32 whu-unetplusplus-efficientnet-b4`. Decoder mode freezes the encoder; lora mode adapts attention projections with a low-rank update and trains the pyramid. Compare both with independently named run directories. CPU teacher inference is the default to limit GPU contention; use --teacher-device cuda only on a separately validated host. Student AMP is BF16, losses/parameters and exported graph are FP32. The CUDA allocator cap excludes ORT and other processes. Every teacher cache uses training rows only; no validation teacher targets, no test optimizer or selection. Validation uses deterministic native crops and supervised multi-head loss. Training sampling is source-group balanced and bounded by within-group hardness, and favors shared-wall crops for half of random draws. No geometric resize or invented CRS.

Outputs contain a hashed ONNX graph, safetensors checkpoint, configuration and training report. LoRA merge and PyTorch/ONNX head parity must pass before publication. Installation under a fresh ID is optional; no existing model is overwritten. The new artifact is usable in the existing inference pipeline, not yet exposed as a resumable managed training job. The report is validation-loss evidence only: compare full-chip Pixel/Object/Boundary metrics against existing models, and independently verify CUDA numerical execution before considering promotion. Test rows are opened for integrity checks but not used in fitting or selection. Keep the independent test locked until the final candidate is frozen.

For a second-stage LoRA run, use the same dataset, backbone and tile size, and add `--mode lora --warm-start DECODER_RUN` with a fresh output directory. The preceding artifact's hashes, supervised split provenance and successful ONNX parity are verified before loading. The dense decoder uses explicit deterministic 2x bilinear arithmetic instead of CUDA interpolate backward. This does not guarantee identical numerical values across hardware/library versions.
