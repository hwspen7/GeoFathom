# Adaptive scientific computing

Open Settings → Computing Resources. Automatic policy uses backend host CPU affinity/cgroup quota, available and total RAM, and shows free storage. Manual mode persists memory fraction, task concurrency, tile size, per-operation cell caps, viewshed extent and ray budget alongside the active database. The effective limits are clamped to real available resources and engineering ceilings. Settings changes are rejected during admitted/queued calculations. A task records its effective snapshot in its result and terrain receipt.

Area statistics and DEM preparation use bounded source windows with exact halo semantics or streamed disk output. Advanced local derivatives use the existing tiled kernels where applicable. Hydrology, visibility, least-cost and encoded GeoTIFF responses still require full grids; their budgets are distinct and conservative. There is no silent resampling, approximation, or independent tile routing. A limit rejection is explicit.

This is a process-local admission estimate, not a new kernel-enforced memory limit. Existing optional OS job/cgroup protection for background workers is unchanged. Terrain API computation remains CPU-only; GPU acceleration and GPU memory budgets are not claimed. Multi-process scheduling, full out-of-core global hydrology/least-cost, resumable jobs, and measured per-operation peak memory/performance on large grids require further independent implementation and acceptance. Public DEM provider download quotas are independent of host settings. The scientific gate and full existing acceptance suites remain enabled.
